# UCI Heart Disease Modeling

An educational machine-learning project using the 303-record UCI Cleveland Heart Disease dataset. The repository preserves the original [`Heart_Modeling.ipynb`](./Heart_Modeling.ipynb) exploration and [`Data_Science_Fundamentals_Final_Project.pdf`](./Data_Science_Fundamentals_Final_Project.pdf) report, and adds a reproducible training pipeline, FastAPI prediction service, and Streamlit dashboard.

> **Disclaimer:** This project is for academic and demonstration purposes only. It is not a clinical diagnosis tool and must not be used to guide medical decisions.

## Architecture

- `src/train.py` downloads UCI dataset 45, selects the 13 standard Cleveland clinical features, binarizes target `num` (0 vs. 1–4), evaluates classifiers, and saves the selected fitted pipeline.
- `api.py` serves health, model metadata, and prediction endpoints.
- `dashboard.py` provides a risk predictor, dataset exploration, and PCA/K-Means patient segmentation. Predictions use the API when reachable and fall back to the local model when it is offline.
- `src/features.py` shares the ordered feature names and descriptions.
- `models/heart_model.joblib` is generated by training and is intentionally not tracked; `models/.gitkeep` retains the directory.

The dataset is fetched from the UCI repository at runtime by both the trainer and dashboard; it is not included in this repository.

## Quickstart

Use Python 3.10 or newer. From the repository root:

```bash
python -m venv .venv
# Activate the virtual environment before continuing.
pip install -r requirements.txt
python src/train.py
```

In separate terminals, start the API and dashboard:

```bash
uvicorn api:app --reload
```

```bash
streamlit run dashboard.py
```

The dashboard opens at Streamlit's local URL. The API docs are available at `/docs`.

## API

### `GET /health`

Returns service status and the active model name.

### `GET /model-info`

Returns the feature schema, random seed, cross-validation results, and held-out test metrics.

### `POST /predict`

Example request:

```bash
curl -X POST "http://127.0.0.1:8000/predict" \
  -H "Content-Type: application/json" \
  -d '{
    "age": 54,
    "sex": 1,
    "cp": 3,
    "trestbps": 130,
    "chol": 240,
    "fbs": 0,
    "restecg": 0,
    "thalach": 150,
    "exang": 0,
    "oldpeak": 1.0,
    "slope": 2,
    "ca": null,
    "thal": null
  }'
```

The response contains the binary prediction, human-readable label, estimated positive-class probability, risk tier, and model name. The risk tier is an educational display band, not a medical assessment.

## Modeling and reproducibility

- A fixed random seed (`42`) is used for NumPy, the stratified train/test split, five-fold `StratifiedKFold`, and classifiers.
- An 80/20 stratified split is made **before** fitting preprocessing. Median imputation and standardization live inside each scikit-learn `Pipeline`, so cross-validation learns preprocessing only from each training fold.
- Logistic Regression and Random Forest are compared using five-fold cross-validation on the training partition. Model selection prioritizes mean recall, then mean F1, to emphasize screening sensitivity. Accuracy, precision, recall, and F1 are also reported on the held-out test set.
- The saved joblib artifact contains the fitted pipeline, ordered feature names, selected model name, seed, and evaluation metrics.
- Dashboard PCA retains 95% of variance; K-Means uses `random_state=42` and `n_init=10`.

Because the data is downloaded dynamically and dependency ranges permit compatible updates, reproducing exact metric values can depend on the upstream dataset and installed package versions.
